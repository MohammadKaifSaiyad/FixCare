## What went well
- **Subagent-driven TDD held up.** RED→GREEN per task + two-stage review (spec then golden-rules/
  fraud/migration agents) caught real issues before merge every time (e.g. the catalog phantom-audit
  and the pincode from→to-zone audit gap).
- **Consistency-over-piecemeal discipline.** Repeatedly chose to keep new code consistent with the
  reviewed module and defer module-wide hardening, rather than let one slice diverge. Recorded the
  deferred items so they're not lost.
- **Brainstorm → design → plan → execute** flow kept scope tight; the addresses out-of-area UX got
  designed deliberately (save + explicit serviceable flag) instead of guessed.

## What hurt / to watch
- **Test-DB migration ledger had silently drifted** — schema was being applied out-of-band and
  `_prisma_migrations` was fictional; a subagent hand-patched it before I caught the root cause and
  reset the test DB cleanly from migrations. Lesson recorded: never hand-patch the ledger; reset from
  migrations. Watch for this on every migration going forward.
- **One subagent dropped its socket mid-task** (A-T3) — re-dispatched cleanly after confirming the tree
  was untouched. Cheap because each task commits independently.
- **Shell CWD drift** (the `cd` into apps/backend persisting) bit a couple of git commands — using
  absolute paths / repo-root cd fixes it.
